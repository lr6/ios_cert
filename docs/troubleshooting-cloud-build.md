# HBuilderX / uni-app 云打包证书问题排查

适用报错：HBuilderX 云打包出现

```
Error code = -5000
Error message: Error: certificate file(p12) import failed!
```

这个错误发生在**导入证书文件**阶段（还没进入编译），所以**与 uni-app / uni-app x 的项目代码、manifest.json、页面配置无关**。
需要检查的是「签名材料」这一对文件：**证书 p12**（必须含私钥）+ **描述文件 mobileprovision**。

---

## 0. 先用一条命令自检

```bash
node scripts/check-signing-assets.mjs <你的证书.p12> <你的描述文件.mobileprovision> <p12密码>
# 只想检查 p12：
node scripts/check-signing-assets.mjs <你的证书.p12> <p12密码>
```

脚本会直接告诉你：

- p12 能不能打开（密码是否正确）；
- **里面到底有没有私钥**（这是“导入失败”最常见的原因之一）；
- 证书 Subject / 类型（Apple Development / Apple Distribution / 企业）、有效期、序列号、TeamID；
- 描述文件的类型（开发 / Ad Hoc / 企业 / App Store）、App ID、过期时间；
- **证书与描述文件是否匹配**（描述文件的 `DeveloperCertificates` 里有没有这张证书）；
- TeamID 是否一致。

退出码 0 = 没发现明显问题，1 = 发现问题（会逐条列出）。

---

## 1. 按可能性排序的原因与处置

| #   | 原因                                                                  | 自检脚本会怎么提示                               | 处置                                                                                             |
| --- | --------------------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| 1   | **p12 密码错误**（含全角/半角、首尾空格、复制粘贴带空格）             | `p12 无法打开：密码错误或文件已损坏`             | 重新导出并记录密码；建议用纯 ASCII 字母数字密码（避免特殊字符在传输中被转义）                    |
| 2   | **p12 里没有私钥**（例如只导出/只上传了证书）                         | `私钥: ✗ 不存在`                                 | 用本工具重新导出（本工具导出的 p12 一定含私钥），或在 macOS 钥匙串里**同时选中证书与私钥**再导出 |
| 3   | **证书与描述文件不匹配**                                              | `✗ 不匹配：描述文件里没有这张证书`               | 到 Apple 后台用**同一张证书**重新生成并下载描述文件；或改用描述文件里包含的那张证书              |
| 4   | **打包类型与证书类型不符**（用开发证书打发布包 / 用发布证书打开发包） | `证书类型: Apple Development（开发证书）` + 提示 | 发布包要用 Apple Distribution 或企业证书；开发调试用 Apple Development                           |
| 5   | **证书/描述文件已过期或被吊销**                                       | `证书已过期` / `描述文件已过期`                  | 到 Apple 后台重新签发证书、重新下载描述文件                                                      |
| 6   | **描述文件类型不对**（开发描述文件含 `get-task-allow`，不能用于上架） | `描述文件是开发类型` / `get-task-allow=true`     | 换成 App Store / 企业分发描述文件                                                                |
| 7   | 上传的文件其实是描述文件 / 文件损坏 / 上传不完整                      | `未找到内嵌的 plist` / `不是有效的 PKCS#12 文件` | 重新选择正确文件并重新上传                                                                       |
| 8   | 对方校验证书链，而 p12 只有叶子证书                                   | `p12 中只有叶子证书，没有中间证书（Apple WWDR）` | 一般不需要；若确认需要，把 Apple WWDR 中间证书一并打包（见第 3 节）                              |

## 2. 本工具生成的 p12 是否“格式不兼容”？（已实测）

社区里确实有“OpenSSL 3 默认参数导出的 p12 在云打包平台导入失败，换成传统参数就好”的情况，所以本项目做过实测（2026-10-12）：

**测试方法**：用领域内最挑剔的老环境 **Java 8（Temurin JDK 8u504，`keytool` / SunJSSE PKCS#12 实现）**，逐一读取四种产物：

| 产物                     | 私钥袋算法                       | 证书袋                        | Java 8 结果                 |
| ------------------------ | -------------------------------- | ----------------------------- | --------------------------- |
| 本工具默认（AES）        | PBES2 + PBKDF2 + AES-256-CBC     | 已加密（PBES2 + AES-256-CBC） | ✓ 可读（`PrivateKeyEntry`） |
| 本工具历史版本           | PBES2 + PKBDF2 + AES-256-CBC     | 未加密（node-forge 默认）     | ✓ 可读                      |
| 本工具「3DES 兼容模式」  | pbeWithSHA1And3-KeyTripleDES-CBC | 已加密（同款 3DES）           | ✓ 可读                      |
| OpenSSL 传统产物（参照） | 3DES                             | 3DES                          | ✓ 可读                      |

结论：**Java 8 能读全部四种**，错误密码也会被正确拒绝。也就是说“我们的 p12 格式导致云打包导入失败”缺乏证据支持 —— 更可能是上面第 1 节里的密码 / 私钥 / 匹配性问题。

不过我们还是做了一处改进：**证书袋默认也加密**（与 OpenSSL、Apple 钥匙串导出的传统 PKCS#12 结构完全一致），并把这一点写进了自动化测试（断言 PBES2/3DES 的 OID 在文件中出现两次 = 私钥袋与证书袋都被加密）。

> 如果某平台仍然只认“最传统”的产物，可以在导出对话框把密钥加密算法切到 **3DES（兼容模式）**，该模式的私钥与证书袋都用 `pbeWithSHAAnd3-KeyTripleDES-CBC` + HMAC-SHA1，和 OpenSSL 1.x / Apple 的产物完全同构。

## 3. 需要把 Apple WWDR 中间证书打进 p12 时

本工具的导出接口支持附加中间证书（`chainPems`），但目前界面尚未暴露该选项。
需要时可以先导出 p12，再用 OpenSSL 追加（需自备 Apple WWDR / WWDR G2 证书）：

```bash
# 1) 从原 p12 解出证书与私钥
openssl pkcs12 -in your.p12 -clcerts -nokeys -passin pass:你的密码 -out leaf.pem
openssl pkcs12 -in your.p12 -nocerts -nodes -passin pass:你的密码 -out key.pem
# 2) 带上中间证书重新打包
openssl pkcs12 -export -out with-chain.p12 \
  -inkey key.pem -in leaf.pem -certfile AppleWWDRCA.pem \
  -passout pass:你的密码 -name "Your Cert Name"
```

（如果这类需求常见，我们可以把“附加中间证书”做成界面上的一个文件选择项。）

---

## 4. 排查顺序建议

1. 跑第 0 节的自检脚本 → 按输出的“发现的问题”逐条处理；
2. 自检没问题时，重点确认**云打包界面里填的密码**与导出时一致，以及**上传的文件确实是刚检查的这一个**；
3. 仍失败时，换一次导出参数（3DES 兼容模式）再试；
4. 还失败，把自检脚本的完整输出 + 云打包日志（含 HBuilderX 版本、证书类型、打包类型）一起提供，继续定位。
